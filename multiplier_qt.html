Theory — Binary Multipliers
What is a Classical Binary Multiplier?
A classical binary multiplier is a digital circuit or algorithm that computes the product of two binary numbers using only the basic operations a CPU already performs — addition and bit shifting. It is the foundation of all arithmetic in modern processors, from simple microcontrollers to supercomputers.
How binary multiplication works

Binary multiplication mirrors the long-multiplication method you learned in school, but in base-2. Every digit is either 0 or 1, so each row of the multiplication table is either zero or an exact copy of the multiplicand, shifted one position to the left for each bit position. These shifted copies are called partial products and are summed together to produce the final result.

The shift-add algorithm automates this: it scans the multiplier bit by bit from the least significant end. When it sees a 1, it adds the current shifted value of the multiplicand into an accumulator register. After each bit, it shifts the multiplicand left by one position and moves to the next bit of the multiplier.

Step-by-step process
1
Load the operands
Place multiplicand A into register M and multiplier B into register Q. Set accumulator ACC to zero. These three registers hold the working state for the entire computation.
2
Inspect the least significant bit
Read the rightmost bit of Q. If it is 1, add the current value of M into ACC. If it is 0, skip the addition — this partial product is zero and contributes nothing to the result.
3
Shift both registers
Shift M one position to the left (multiply its positional weight by 2) and shift Q one position to the right (discard the bit just processed and expose the next one). This is a single-cycle operation on any CPU.
4
Repeat until done
Go back to step 2. The loop runs exactly n times, where n is the number of bits in B. Once Q reaches zero there are no more bits to process.
5
Read the result
The accumulator ACC now holds the complete product of A × B. Its maximum width is 2n bits — twice the width of the inputs — so the result register must be wide enough to hold the largest possible product.
Worked example — 5 × 6
Example
A = 0101 (decimal 5)   B = 0110 (decimal 6)
─────────────────────────────────
Cycle 1 → LSB = 0 → skip   M = 01010
Cycle 2 → LSB = 1 → ACC += 01010    ACC = 01010
Cycle 3 → LSB = 1 → ACC += 010100   ACC = 011110
Cycle 4 → LSB = 0 → skip   done
Result = 011110 = decimal 30   ✓   (5 × 6 = 30)
Performance characteristics
Time complexity
O(n) — Linear
The number of cycles grows directly with the number of bits in B. Double the bits, double the cycles. Every bit requires one shift and at most one add.
Space complexity
O(n) — Linear
Three registers of width n (M, Q) and 2n (ACC) are needed. No extra memory is required — the computation is entirely in-register.
Parallelism
Sequential only
Each cycle depends on the previous one. You cannot start cycle 3 before cycle 2 completes. This sequential dependency is the core bottleneck of classical multiplication.
Reliability
Fully deterministic
Given the same inputs the output is always identical. No probability, no error rate, no need for error correction. This is what makes it the universal standard today.
Real-world variants: The basic shift-add is the conceptual foundation. Modern processors use optimised variants — Booth's algorithm reduces partial products by up to half, and Wallace tree multipliers compute all partial products simultaneously using carry-save adders, reducing gate delay to O(log n). But all of them trace back to the same shift-and-add logic described here.
Deterministic Sequential O(n) cycles CPU / ALU No error correction needed
What is a Quantum Binary Multiplier?
A quantum binary multiplier is a quantum circuit that computes the product of two numbers by encoding them as qubits and exploiting superposition and entanglement to evaluate all partial products at the same time, rather than one at a time. It is a theoretical model that demonstrates the potential of quantum computing for arithmetic at very large scales.
Key quantum concepts
Concept 1
Qubit
Unlike a classical bit which is strictly 0 or 1, a qubit can exist in a blend of both states simultaneously. This blend is called superposition. Physically it is often a photon's polarisation, an electron's spin, or a superconducting loop's current direction.
Concept 2
Superposition
When a qubit is placed in superposition via a Hadamard gate, it simultaneously represents both 0 and 1. A register of n qubits in superposition can represent all 2ⁿ possible values at once, allowing a single circuit pass to explore every combination in parallel.
Concept 3
Entanglement
Two qubits can be entangled so that measuring one instantly determines the state of the other, regardless of distance. In a multiplier circuit, entanglement links the input qubits to the output register, encoding the product relationship into the quantum state itself.
Concept 4
Measurement
Reading a qubit collapses its superposition to a definite 0 or 1. The circuit is designed so that when measurement happens, the probability of reading each output bit is overwhelmingly biased toward the correct product. This is quantum interference doing useful work.
How the quantum multiplier works

The quantum multiplier encodes the two operands A and B into two qubit registers. The B register is then put into superposition using Hadamard gates, making each qubit of B simultaneously 0 and 1. Controlled phase gates then entangle each qubit of B with a shifted copy of A — this is equivalent to computing every partial product simultaneously. A quantum Fourier transform then combines the phases so that when the output register is measured, it collapses to the binary representation of the product A × B.

The critical insight is that the circuit does not iterate — it evaluates all 2ⁿ multiplication paths through quantum interference in parallel, completing in a constant number of circuit layers regardless of input size.

Circuit phases
1
Initialisation — encode the inputs
Load A and B as classical binary values into two separate qubit registers. At this stage the qubits are in definite states (|0⟩ or |1⟩) — no superposition yet. This corresponds to the "Init" phase shown in the simulator.
2
Superposition — apply Hadamard gates
Each qubit of the B register is passed through a Hadamard (H) gate, placing it into an equal superposition of |0⟩ and |1⟩. The register now simultaneously represents every possible bit pattern of B — all partial product conditions exist at once.
3
Entanglement — controlled gates
Controlled-phase (CPHASE) or Toffoli gates link each B qubit to a shifted version of the A register. This writes the multiplication relationship — every partial product — into the phase of the quantum state without collapsing the superposition.
4
Interference — Quantum Fourier Transform
A QFT is applied to the output register. Probability amplitudes of wrong answers cancel out through destructive interference while the amplitude of the correct product is reinforced through constructive interference — this is how the circuit "chooses" the right answer.
5
Measurement — read the result
Measuring the output register collapses the quantum state to the product A × B with very high probability. This is the only step the outside world sees — the entire parallel computation happened invisibly inside the quantum state. In the simulator this is shown as "Cycle 2".
Performance characteristics
Circuit depth
O(log n)
The number of gate layers grows logarithmically. Doubling the input size adds only one extra layer, not double the work. This is the fundamental advantage over classical O(n) multiplication.
Parallelism
Full superposition
All 2ⁿ partial product computations happen simultaneously inside the quantum state. No sequential loop exists. The circuit depth is determined by the longest chain of dependent gates, not the number of bits.
Output type
Probabilistic
The result is correct with high probability, not certainty. Error correction codes and repeated measurement are used to boost confidence. Current NISQ hardware introduces additional noise that reduces this probability.
Hardware requirement
QPU — Quantum Processor
Requires a quantum processing unit with low decoherence times, high gate fidelity, and qubit connectivity matching the circuit topology. No classical computer can run a true quantum multiplier — only simulate it exponentially slowly.
Important caveat: The "2 cycles" shown in this simulator is a pedagogical simplification of the two logical phases — initialisation and measurement. A real quantum multiplier for two 4-bit numbers would require dozens of physical gate operations and tens of physical qubits after accounting for error correction overhead. Quantum advantage over classical multipliers is not yet practical on today's hardware — it is a near-future milestone, not a present reality.

Why compare these two approaches?
Both multipliers produce the same result — the product of two binary numbers. The difference is entirely in how they get there. Understanding that difference reveals the fundamental gap between classical sequential computation and quantum parallel computation.
Side-by-side comparison
Classical — Shift-Add
  • Processes one bit of B per cycle
  • Each cycle depends on the last
  • n cycles for an n-bit input
  • Always gives the exact correct answer
  • Runs on any CPU available today
  • No special hardware required
  • No error correction overhead
  • Performance bottleneck: sequential loop
Quantum — Bloch Model
  • All bits of B processed simultaneously
  • Circuit layers are independent
  • O(log n) layers for an n-bit input
  • Answer correct with high probability
  • Requires a quantum processor (QPU)
  • Needs hundreds of physical qubits
  • Requires error correction overhead
  • Performance bottleneck: decoherence

The key trade-off
Classical strength
Reliability & availability
Classical multipliers are exact, fast enough for virtually all current use cases, and run on hardware that costs pennies. For inputs under a few thousand bits, they are unbeatable in practice.
Quantum strength
Scalability at large n
As input sizes grow into thousands or millions of bits — relevant for cryptography and scientific computing — the O(log n) depth of a quantum circuit would make it exponentially faster than any classical approach, if reliable QPUs existed.
Classical weakness
Sequential scaling
Every extra bit added to the input adds exactly one more cycle. For cryptographic key sizes (2048+ bits), even optimised classical multipliers are slow — and this is exactly why quantum computing threatens RSA encryption.
Quantum weakness
Hardware immaturity
Current quantum computers cannot run a reliable multiplier for inputs larger than a few bits. Decoherence, gate error rates, and qubit connectivity constraints make the physical overhead enormous compared to the theoretical circuit depth.
Bottom line: Use classical multiplication for everything today. Study quantum multiplication to understand where computing is heading — especially in cryptography, optimisation, and simulation — and why fault-tolerant quantum processors are one of the most important engineering challenges of this decade.
